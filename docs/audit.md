# Аудит сохранённого DOM Ozon

Аудит выполнен по `ozon-dom.html` от 4 ноября 2026 года. Это статический снимок после выполнения JavaScript, а не дерево доступности Chromium. Чувствительные параметры URL, служебное состояние и данные сеанса здесь не приводятся.

## Итоги

| Проверка | Результат в fixture |
| --- | ---: |
| `h1`–`h6` и `[role="heading"]` | 0 |
| `header` / `main` / `nav` / `footer` | 1 / 0 / 0 / 1 |
| Кнопки | 224 |
| Кнопки без имени, определимого из текста, `aria-label`, `title` или `alt` | 216 |
| Ссылки | 168 |
| Ссылки без имени по той же статической оценке | 73 |
| Товарные ссылки / уникальные товары | 140 / 70 |
| Товарные ссылки без имени | 70 |
| Поисковые поля | 1 |
| Явные ARIA-атрибуты | 56 (`aria-label`: 1, `aria-hidden`: 55) |
| Ненативные фокусируемые элементы | 1 |

Явных оборванных ссылок `aria-labelledby`, неизвестных значений `role` или конфликтов нативной роли с явной ролью в fixture нет. Отсутствие явного `role` у `header`, `footer`, `button` и `a[href]` не является ошибкой.

## Подтверждённые проблемы и исправления

### Нет структуры заголовков

В DOM нет ни одного заголовка. Каждая карточка при этом содержит отдельную текстовую ссылку с названием товара:

```html
<a href="/product/.../"><span>Название товара</span></a>
```

Расширение помечает содержащий название `span` как заголовок уровня 2. Роль ссылки остаётся у родительского `a`, дубликат заголовка для ссылки-изображения не создаётся.

### Нет основного ориентира и навигации

Содержимое находится в отдельном контейнере `data-widget="wallpaper"`, содержащем `data-widget="tileGridDesktop"`; он не включает `header`. Этому существующему контейнеру добавляются `role="main"` и имя. Горизонтальному меню добавляются ориентир навигации и имя, контейнеру поиска — нативные имена его подтверждённых элементов.

### Половина товарных ссылок не имеет имени

На каждый из 70 товаров приходится две ссылки с одинаковым путём `/product/.../`: ссылка-изображение без `alt` и текстовая ссылка с названием. Расширение группирует ссылки по нормализованному пути и переносит достоверное название в `aria-label` только безымянной ссылки. `href`, обработчики и открытие в новой вкладке не меняются.

### Поиск по изображению

Рядом с единственным полем `placeholder="Искать на Ozon"` есть подписанная кнопка отправки «Поиск» и отдельная безымянная кнопка с SVG камеры. Комбинация назначения виджета, типа кнопки и соседней подписанной кнопки подтверждает название «Поиск по изображению».

### Элемент входа

Статический fixture и повторная live-проверка показывают `data-widget="profileMenuAnonymous"` как фокусируемый `div` без роли и явного имени. В живом AX-дереве он может полностью отсутствовать. OzonAccess добавляет `role="button"`, `aria-label="Войти"` и недублируемый мост Enter/Space, сохраняя исходный `tabindex` и обработчики клика Ozon.

## Неисправленные и требующие браузерной проверки элементы

- 215 кнопок после подтверждённого исправления поиска остаются без статически определимого имени. Среди них повторяются SVG-стрелки каруселей и кнопки с иконкой сердца, но одного рисунка и динамического CSS-класса недостаточно, чтобы безопасно назначить смысл или состояние.
- Три нетоварные ссылки не имеют имени по статической оценке.
- В fixture нет явных `aria-expanded` и `aria-pressed`; состояния меню, каруселей и избранного нужно проверить в реальном дереве доступности.
- Видимость, порядок Tab, ловушки фокуса, активация Enter/Space и объявления NVDA не устанавливаются из HTML-снимка.
- Встроенный CSS fixture содержит как минимум два синтаксически некорректных блока; это не относится к коду расширения, но ограничивает точность автономного рендера.

Диагностический отчёт доступен в `window.__ozonAccessReport` и выводится в консоль. Он не отправляется по сети.

## Ручная проверка

В Chromium с NVDA проверить навигацию клавишами H/2/D, чтение обоих вариантов товарной ссылки, работу поиска, каруселей, избранного, меню входа и порядок Tab после динамической подгрузки. Автоматические проверки не подтверждают полное соответствие WCAG 2.2 AA.
